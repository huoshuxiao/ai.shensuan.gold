# 国内黄金量化投资设计

> 版本：v1.0（2026-10-29）
> 定位：在现有硬件（16GB 内存、2GB 显存、i7-6700HQ、Ubuntu 20.04、Python 3.10）上，面向国内黄金 ETF 的**多头、人工执行、可审计**量化投资设计。
> 关系：本文件是对 `AGENTS.md` 投资设计的专业评审与替代方案；`AGENTS.md` 的数据工程、PIT、质量闸、禁止券商接口、人工下单等约束继续有效。两者冲突时，以本文件§9 的修改清单为准；在回写 `AGENTS.md` 之前，`AGENTS.md` 仍是工程行为规范。
> 声明：本文件不构成投资建议，不承诺收益；所有参数都是待回测校准的起点，不是已验证结论。系统不接券商、不自动下单、不保存账号/密码/令牌。

---

## 0. 一页结论

### 0.1 对 `AGENTS.md` 的判断

`AGENTS.md` 的**数据工程与审计设计明显强于它的投资逻辑**。P1 已经把原始快照、PIT、质量闸、能力封锁、人工下单边界做得很扎实；但投资部分仍有三个过强的假设：

1. **七组特征加权分数**（趋势 30% + 动量 15% + 波动率 15% + 跨市场 15% + 流量 10% + 宏观 10% + 地缘 5%）把高度相关的价格类因子重复计数，权重是设计起点而非回测结果；宏观/地缘/流量数据还有大量缺失或修订，实际可用性支撑不了这个权重表。
2. **9 角色、两轮辩论、每日 07:35 出结论**的 LLM 委员会，在 16GB/2GB CPU 机器上运行成本高、非确定性强、叙事偏差大，而且没有证据表明它能稳定增加风险调整后收益。它适合做研究/解释，不适合做每日仓位决策。
3. **每日决策、09:30 人工执行、30% 卫星仓**的节奏，把黄金这种慢变量资产做成了高频噪声交易：隔夜跳空、ETF 溢价、人工执行滑点和换手成本都会吃掉本来就很薄的战术收益。

### 0.2 本设计的替代方案

- **战略核心 + 小型战术卫星 + 现金**：默认核心 70%（允许 60–80%），卫星 0–20%（硬上限 30%），现金为剩余；只做多、不加杠杆、不做空、不交易期货。
- **只保留少量独立信号**：200 日趋势/斜率、20 日已实现波动、回撤阶梯；宏观、跨市场、流量、地缘只做**降险/执行过滤**，不参与加仓打分，直到样本外验证通过。
- **每周决策、每日风控监控**：周五收盘后计算，下一交易日 09:45–10:30 限价执行；风险闸和极端事件可以每日触发减仓，但不做每日择时。
- **LLM 默认关闭**：v1 用确定性引擎；如保留 LLM，只做 3 角色、单轮、只读事实包的 shadow 研究，不输出目标仓位，不进入人工清单。
- **先证伪再上线**：P2 特征/事实包 → P3 回测与预注册 → P4 纸面 20 日 → P5 LLM shadow 8–12 周 → 用户签字；任何一步不通过就退回 B2（70/30 静态基准），不强行上线策略。

### 0.3 最重要的五个非硬件修改

| 优先级 | 修改 | 原因 |
|---|---|---|
| P0 | 9 角色 LLM 决策委员会降为可选 shadow；v1 目标仓位由确定性引擎决定 | 硬件、时延、非确定性、无 alpha 证据 |
| P0 | 七组加权分数改为“核心 + 趋势/波动/回撤风险叠加”；宏观/流量/地缘只降险 | 避免相关因子重复计数与过拟合 |
| P1 | 每日 07:35 决策改为每周决策 + 每日风控监控 | 降低换手、隔夜跳空和执行噪声 |
| P1 | 卫星默认 20%、硬上限 30%；核心 70% 作为用户政策而非固定真理 | 控制跟踪误差和回撤 |
| P1 | 回测补齐 ETF 溢价/折价、分红、T+0/T+1、涨跌停、集合竞价、跟踪误差 | 当前回测口径不足以支持实盘结论 |

## 1. 评审范围与结论

### 1.1 保留：`AGENTS.md` 已经做对的部分

以下内容不建议改，P2–P8 继续沿用：

- **PIT 与数据证据链**：`as_of/available_at/fetched_at/source/ingest_run_id/vintage/quality`；原始快照 append-only；坏行留档；质量报告与 `doctor` 能力清单。
- **失败关闭**：数据 RED/过期/账本断链/配置哈希不符时只减不加；缺失不填 0、不插值、不用 LLM 猜。
- **人工交易边界**：不接券商、不自动下单、不保存凭证；只产出研究、决策卡、纸面台账和人工下单清单。
- **哈希与审计**：事实包哈希、配置哈希、决策哈希、纸面账本哈希链；可复现边界写清楚。
- **非专业可读性**：决策卡要求“今天做什么、为什么、错了会怎样、不做什么”，这条比很多量化系统都强。
- **测试分层与结构治理**：unit/contract/integration/architecture 四层、docstring、PROJECT.md 回写、配置注释。
- **P1 程序化验收**：`accept --stage P1` 的判据化验收，比“人眼看 CSV”可靠。

这些是系统的地基，不应该为了“更像 AI 对冲基金”而牺牲。

### 1.2 需要修改：投资逻辑的五个薄弱点

#### 1.2.1 七组权重是“因子动物园”

`AGENTS.md` §8.2 的权重表把趋势、动量、波动率分开加权，但三者都来自同一价格序列：

- 趋势（MA200/MA60 斜率、价格位置）
- 动量（1/5/20/60 日收益、RSI）
- 波动率（RV20/RV60、分位）

在黄金日频数据上，这三组的横截面相关性通常很高；把它们相加，会让“价格趋势”实际获得 60% 的显式权重，却看起来像三个独立证据。跨市场基差、CFTC/SPDR、GPR 又分别有数据延迟、低覆盖和修订问题。结果是一个**参数很多、独立信息很少**的分数。

**修改**：生产 v1 不再用七组加权分数决定仓位。改用“风险预算 + 趋势方向 + 波动缩放 + 回撤闸”的分层结构；宏观/流量/地缘只做降险或执行过滤。七组分数保留为研究模型，用于 P3 对照，不作为默认决策。

#### 1.2.2 宏观/地缘权重与数据可用性不匹配

- `MAC_TIPS10Y` 没有稳定直连；`MAC_DXY_PROXY` 是代理；`MAC_US10Y` 历史只从 2021 年起。
- GPR 是 `REVISED_ONLY`，不能用于晋升；事件 severity 还要人工复核。
- SPDR 历史覆盖率低（P1 `LOW_COVERAGE`），CFTC 是周频且按发布日滞后。
- COMEX/WTI 的 volume/open_interest 全为 0，不能当流动性或流量信号。

给这些数据合计 25% 的权重（宏观 10% + 流量 10% + 地缘 5%），会让“缺失/降级/修订”直接变成仓位噪声。

**修改**：在数据能力清单（`_remediation.json`）允许之前，这些组不得进入加仓打分；只能作为降险 overlay 或展示项。GPR 在建立 vintage 前不参与任何晋升统计。

#### 1.2.3 9 角色 LLM 委员会不适合本机每日决策

`AGENTS.md` §11.1/§11.3 要求 9 个角色、两轮、每个角色 50s/45s、总预算 12min，模型默认 `deepseek-r1:8b`，CPU 推理、`num_gpu=0`。在 16GB/2GB 机器上：

- 8B/9B 的 Q4 权重加 KV cache 会占用数 GB；`LLM_MIN_FREE_GB=9.5` 目前是占位值，P1 预检实测可用内存只有 4.93 GiB（2026-10-23 验收读数），并不能证明 9B 能稳定起。
- 9 个角色 × 50s 已是 7.5min，加模型加载、解析、重试、两轮汇总，12min 很紧；冷启动可能十余分钟。
- LLM 输出非确定；即使温度 0，也不能承诺逐位复现；多角色长文会放大叙事偏差和“看起来有道理”的风险。
- 没有任何证据表明 9 角色辩论比一个简单的趋势/波动规则有更高的风险调整收益。

**修改**：v1 的 `mode=off`，目标仓位由确定性引擎给出；LLM 只做研究/解释，最多 3 个角色、单轮、只读事实包、不输出目标仓位。若用户坚持 9 角色，改成每周一次 shadow，且 8–12 周评估前不得进入人工清单。

#### 1.2.4 每日决策与 30% 卫星仓不匹配黄金的慢变量特征

黄金的趋势/实际利率/美元/央行需求都是慢变量；每日 07:35 出结论、09:30 人工执行，会把：

- 隔夜 COMEX/美元跳空变成执行风险；
- 微小信号变化变成换手和佣金；
- 人工执行延迟变成跟踪误差；
- 30% 卫星仓放大择时错误。

**修改**：每周决策（周五收盘后），下一交易日 09:45–10:30 限价执行；每日只做数据/风险监控和极端事件减仓。卫星默认 20%，硬上限 30%；核心 70% 作为用户政策，允许 60–80% 漂移，季度再平衡。

#### 1.2.5 回测口径缺少 ETF 真实交易细节

当前 §12.3 已有 T+1 开盘、100 份整手、费用/滑点、涨跌停/停牌，但还缺：

- ETF 溢价/折价（price vs NAV/iNAV）；
- 分红/拆分/复权；
- 集合竞价/开盘冲击/成交量约束；
- 跟踪误差与基金费用；
- 现金利息与现金拖累；
- 数据发布日期与可交易时点的对齐。

没有这些，回测容易把“收盘价信号 + 开盘价成交”做成过于乐观的结果。

**修改**：P3 回测必须补齐这些口径；没有 NAV/iNAV 数据时，明确标记为 `MISSING` 并做保守假设（例如溢价过滤不可用则只交易主 ETF、提高滑点），不得用 0 或猜测替代。

### 1.3 设计取舍

| 选择 | 本设计 | 理由 |
|---|---|---|
| 决策核心 | 确定性规则 | 可复现、可审计、成本低 |
| LLM | 默认 off，最多 shadow | 硬件与证据都不支持每日决策 |
| 资产 | 国内黄金 ETF 为主 | 流动性、T+0、无杠杆、人工可执行 |
| 方向 | 只做多 | 用户约束；不做空、不加杠杆 |
| 频率 | 每周决策 + 每日风控 | 匹配黄金慢变量，降低换手 |
| 仓位 | 核心 70% + 卫星 0–20%（硬上限 30%） | 控制跟踪误差与回撤 |
| 复杂因子 | 研究/展示，不直接加仓 | 避免过拟合与数据缺失噪声 |
| 验证 | 预注册 + 样本外 + 成本后 | 先证伪，再上线 |

## 2. 投资目标、资产与约束

### 2.1 资金边界

- 系统管理的是用户**单独划定的黄金 sleeve**，不是用户总资产。
- `core + satellite + cash = 100%`；`cash ≥ 0`；不隐含杠杆、不融资、不做空。
- 系统不知道用户总财富、税况、负债和风险承受力；决策卡必须写明“这是黄金 sleeve 内百分比”。
- 若用户把黄金 sleeve 作为总资产的一部分，需在系统外自行做总资产层面的风险预算；本系统不替用户做资产配置。

### 2.2 资产清单

| 资产 | 角色 | 是否默认交易 | 口径/限制 |
|---|---|---|---|
| `518880` 黄金 ETF | 主交易标的 | 是 | 100 份整手；T+0；有涨跌停；关注溢价/折价与流动性 |
| `159934` 黄金 ETF | 备用/替代 | 条件性 | 流动性与跟踪误差需实测；不与 518880 同时满仓 |
| SGE `Au99.99` | 人民币金价基准 | 否 | CNY/g；用于基差/溢价参考，不直接交易 |
| SHFE `AU0` | 国内期货研究基准 | 否 | 有杠杆、换月跳空；只研究，不进入默认清单 |
| COMEX `GC` | 美元金价基准 | 否 | USD/oz；只当收盘价，零成交量不可当流动性 |
| `USD/CNY` | 汇率换算 | 否 | BOC 折算价与 SAFE 中间价二选一，不拼接 |
| 现金 `CNY` | 组合剩余 | — | 不得为负；不计入黄金 beta |

### 2.3 约束

- 硬件：16GB 内存、2GB 显存、i7-6700HQ；不假设 GPU 推理；不并发多个本地模型。
- 执行：人工下单，系统只给清单；不接券商、不保存凭证、不自动交易。
- 数据：公开接口 + 手工 CSV；源不稳定时降级/标缺失；不购买未授权数据。
- 合规：不构成投资建议；不对外分发受限数据；不承诺收益。
- 软件：Python 3.10；依赖经 `requirements.txt`；Docker 可选；单机、无数据库/消息队列。
- 工程沿用 `AGENTS.md`：JSONL 日志按日轮转、保留 7 天；测试按 unit/contract/integration/architecture 分层；任务 `DONE` 才 commit、不 push；运行链路节点状态写 `pipeline_status.json`。
- RD-Agent 只做因子研究，不直接改生产配置/特征注册表，不直接晋级因子；与本地 LLM 单实例互斥。

### 2.4 成功标准（评估口径，不是收益承诺）

本系统不承诺“跑赢金价”。P3/P8 的评估目标是：

1. **风险调整后不劣于基准**：样本外 Sharpe 不低于 B1（100% 518880）超过 0.10，且最大回撤至少改善 3 个百分点；或 Calmar 有可解释改善。
2. **成本后仍成立**：佣金、滑点、整手、溢价/折价、跟踪误差全部计入；成本加倍后结论不反转。
3. **可执行**：订单不超过 20 日 ADV 的 5%；价格带内可成交；人工执行不依赖盘中盯盘。
4. **可审计**：每个决策有 `fact_id`、来源、`as_of`、`available_at`、配置哈希与决策哈希。
5. **不越界**：全仓库无券商/自动下单路径；LLM 不决定真实仓位。
6. **可停止**：任何阶段不通过就退回 B2，不强行上线。

若以上风险调整目标达不到，**默认使用 B2（70% 518880 + 30% 现金，月度/季度再平衡）**，而不是硬上战术策略。对非专业用户，“不劣于简单基准”比“复杂策略看起来聪明”更重要。

## 3. 策略设计

### 3.1 总体框架

```text
gold sleeve = core + satellite + cash
core      : 战略黄金 beta，默认 70%，允许 60–80%
satellite : 战术卫星，默认 0–20%，硬上限 30%
cash      : 剩余，≥0；用于再平衡和风险缓冲
```

不变量：

```text
0 ≤ core ≤ 100%
0 ≤ satellite ≤ min(30%, 100% - core)
cash = 100% - core - satellite ≥ 0
```

核心是“用户政策仓”，不是 alpha；卫星才是战术层。核心不参与每日/每周择时，只在季度或漂出 60–80% 时再平衡。

### 3.2 核心仓

- 默认 `core_target = 70%`；用户可在 60–80% 之间设定。
- 核心再平衡触发：`core < 60%` 或 `core > 80%`，按季度检查；用价格带分批，不在单日一次打完。
- 核心不使用 LLM、不使用地缘事件、不使用短期 RSI。
- 核心的基准是 B1/B2；核心跑输 B1 是正常的，因为它保留了现金/卫星空间。

### 3.3 卫星信号：只保留三个独立维度

#### 3.3.1 趋势（方向）

使用 518880 收盘价（前复权，若数据可得）：

```text
ma200_t   = mean(close, 200)
slope20_t = ma200_t / ma200_{t-20} - 1
on_t      = close_t > ma200_t * (1 + 0.01) and slope20_t > 0.005
off_t     = close_t < ma200_t * (1 - 0.01) and slope20_t < -0.005
```

- `on`/`off` 使用滞回：一旦进入某状态，只有反向条件满足才切换；中间区域保持上一状态。
- 可选用 6 个月动量做确认：`mom6_t = close_t / close_{t-126} - 1`；只有 `mom6 > 0` 才允许 `on`，但**不单独用 RSI/MA60 再算一遍**，避免重复计数。
- 趋势状态 `trend_t ∈ {0, 1}`：`on=1`，`off=0`，中间保持上一状态。
- 指标在 T 日收盘后计算；T+1 才允许交易，禁止用 T 日收盘价成交。

#### 3.3.2 波动率（风险预算）

```text
r_t     = ln(close_t / close_{t-1})
RV20_t  = sqrt(252) * std(r, window=20)
vol_scale_t = min(1, target_vol / max(RV20_t, 0.05))
```

- `target_vol` 默认 12%（可配置 10–15%）。
- `RV20 < 5%` 时按 5% 计，避免低波动时把卫星放大到不合理水平；仍然不加杠杆。
- `RV20 > 30%` 时卫星上限降至 10%；`RV20 > 35%` 时卫星为 0。
- 样本不足 20 日：卫星为 0，标 `DEGRADED`，不得用历史均值代替。

#### 3.3.3 回撤（风险闸）

以黄金 sleeve 的历史高水位（含现金，按日估值）计算：

```text
DD_t = 1 - NAV_t / max(NAV_{0..t})
dd_scale_t = 1.0   if DD < 10%
             0.5   if 10% ≤ DD < 15%
             0.0   if DD ≥ 15%
```

- `DD ≥ 20%`：熔断，停止新增风险；必须人工书面重启。
- 回撤阈值是初始值，P3 要用黄金 2011–2015 等历史段校准；若用户风险承受力更低，可整体下调。
- 回撤是风险减仓方向，不受换手/噪声带限制。

### 3.4 卫星仓位公式

```text
satellite_target =
    S_max
    × trend_t
    × vol_scale_t
    × dd_scale_t
    × overlay_multiplier_t
```

其中：

- `S_max = 20%`（默认）；用户可在 P3 后提高到 30%，但不得超过硬上限。
- `overlay_multiplier_t ∈ [0, 1]`：宏观/流量/地缘/流动性 overlay **只能降低**卫星，不能提高；默认 1。
- 若 `satellite_target < 3%`，按 0 处理（噪声带）。
- 最终 `satellite_target = min(satellite_target, 30%, 100% - core)`。
- `cash = 100% - core - satellite_target`；不得为负。

### 3.5 宏观、跨市场、流量、地缘的角色

这四类信息不作为加仓打分的独立权重；它们只做以下三类事情：

#### 3.5.1 降险 overlay

| 信息 | 可用条件 | 动作 |
|---|---|---|
| 实际利率/美元 | TIPS 或可靠代理为 GREEN | 实际利率快速上行 + 美元走强 → `overlay_multiplier` 下调 25–50% |
| CFTC 净仓 | 周频，按发布日 PIT | 净仓 z ≥ +1.5（拥挤）→ 下调 25%；z ≤ -1.5 不加仓（逆向仅研究） |
| SPDR 流量 | 覆盖率达标且非 LOW_COVERAGE | 4 周极端流入 → 下调 25%；极端流出只展示，不加仓 |
| GPR/事件 | GPR 有 vintage 或实时快照；事件 severity 已复核 | GPR z ≥ 1.5 且 RV 分位 ≥ 80% → 卫星不得增加；只减不加 |
| 流动性/溢价 | ETF 溢价/成交额可用 | 溢价超过阈值 → 不买；折价超过阈值 → 不卖；ADV 不足 → 降单笔 |

#### 3.5.2 执行过滤

- `SGE 溢价 = SGE_Au99.99 / (GC × USDCNY / 31.1034768) - 1`：用于判断国内金价是否过度偏离国际金价；极端溢价不追买，极端折价不恐慌卖。
- `ETF 溢价 = ETF_price / NAV - 1`：若 |溢价| > 0.5%，不按市价追；没有 NAV/iNAV 时标 `MISSING`，只交易主 ETF 并提高滑点假设。
- 这些是执行时机，不是独立 alpha。

#### 3.5.3 展示与研究

- GPR、CFTC、SPDR、新闻事件进入事实包/UI，供解释和人工复核。
- “别人贪婪时恐惧/别人恐惧时贪婪”只做研究统计（当前 §8.4.2 的做法正确），未通过预注册样本外前不加仓。
- LLM 不得引用这些字段作为加仓理由；只能做风险提示。

### 3.6 再平衡与执行

#### 3.6.1 频率

- **每周决策**：周五收盘后（或最后一个交易日收盘后）计算，下一交易日执行。
- **每日监控**：数据质量、回撤、波动率、极端事件；只有风险减仓/熔断可以每日触发。
- 若用户坚持每日决策：只在 `|satellite_target - current| ≥ 3pp` 时交易；否则不动作；仍然禁止用当日收盘价成交。

#### 3.6.2 执行窗口

- 09:45–10:30（避开开盘 15 分钟和午间/尾盘流动性变化）；使用限价单。
- 价格带：参考前收/开盘 ±2%，或买卖价差 + 1%；超过价格带不追价，记 `UNFILLED`。
- 最大滑点：基准 5bps，压力测试 15bps；超过不成交。
- 100 份整手；不足一手不交易；剩余进现金。
- 518880 为主；159934 只在 518880 流动性异常/溢价异常时替代，且需人工确认。
- ETF 支持 T+0，但策略按 T+1 执行，避免用当日收盘信息在同一收盘成交的未来函数。

#### 3.6.3 成本

| 项目 | 默认 | 说明 |
|---|---:|---|
| 佣金 | 2.5bps，最低 5 元 | 按用户券商实际可调 |
| 滑点 | 5bps | 压力测试 15bps |
| 印花税 | 0 | 黄金 ETF 通常免印花税；以券商为准 |
| 过户/经手费 | 按实际 | 计入成本 |
| 冲击成本 | ADV 5% 上限 | 大单拆分/延后 |
| 现金收益 | 0 或保守值 | 不计入黄金 beta |

#### 3.6.4 分红/拆分/复权

- 518880/159934 的分红、拆分必须进入总收益计算；不能只用不复权价格。
- 若数据源没有复权因子，使用“价格 + 现金分红”的手工表，或在回测中明确标 `PRICE_ONLY` 并下调结论置信度。
- 不使用未来才知道的复权因子；复权因子必须按公告日 PIT。

### 3.7 明确不做

- 不做空、不加杠杆、不交易期货、不做 T+0 日内回转。
- 不用 7 组加权分数直接决定仓位。
- 不用 LLM 输出目标仓位。
- 不用 GPR/新闻/地缘事件加仓；未通过预注册前只减不加。
- 不用缺失值填 0、前值、均值或 LLM 猜测。
- 不把“黄金是避险资产”当无条件假设；黄金也会出现 20%–45% 的回撤。
- 不把单次战争/制裁/ETF 流入剪成故事来证明策略有效。

### 4.2 建议新增的数据（P2 先验证再纳入）

2. **ETF 分红/拆分/复权因子**：基金公告；用于总收益。
3. **SGE 成交量/持仓**（若可得）：用于国内金价流动性判断。
4. **TIPS 实际利率或可靠的盈亏平衡通胀**：没有就标 `MISSING`，不要用名义利率冒充实际利率。

6. **国内黄金 ETF 份额/资金流**：若可得，用于流量研究；没有就标 `MISSING`。
7. **交易日历**：境内用上交所日历；美国/外汇用近似口径并披露（P1 已有部分）。
8. **基金费率/跟踪误差**：用于回测净收益。

新增数据必须过：PIT、质量闸、契约测试、能力清单；不能因为“看起来有用”就进入事实包。

### 4.3 特征定义

| `fact_id` | 公式/口径 | 用途 | 缺失策略 |
|---|---|---|---|
| `TRD_MA200` | `mean(close,200)` | 趋势 | 样本不足 → `MISSING` |
| `TRD_SLOPE20` | `MA200_t/MA200_{t-20}-1` | 趋势 | 同上 |
| `MOM_6M` | `close_t/close_{t-126}-1` | 趋势确认 | 样本不足 → `MISSING` |
| `VOL_RV20` | `sqrt(252)*std(ln(P_t/P_{t-1}),20)` | 波动缩放 | 样本不足 → `DEGRADED`，卫星 0 |
| `RISK_DD` | `1-NAV/high_water` | 回撤闸 | 账本缺失 → 停止 |
| `XMK_SGE_PREMIUM` | `SGE/(GC*USDCNY/31.1034768)-1` | 执行/溢价 | 任一缺失 → `MISSING` |
| `XMK_ETF_PREMIUM` | `ETF_price/NAV-1` | 执行/溢价 | 无 NAV → `MISSING` |
| `MAC_REAL_YIELD` | TIPS 10Y 或可靠代理 | 降险 overlay | 无数据 → `MISSING`，不启用 |
| `FLOW_CFTC_Z` | CFTC 净仓 3 年 z 分 | 拥挤度降险 | 周频/发布滞后 |
| `FLOW_SPDR_Z` | SPDR 4 周流量 z 分 | 流量降险 | 低覆盖 → 只展示 |
| `GEO_GPR_Z` | GPR 252 日 z 分 | 地缘降险 | 无 vintage → 只展示 |

注意：

- `TRD_MA200`、`MOM_6M`、`VOL_RV20` 都来自价格；不要把它们当成三个独立 alpha。它们是“方向/风险缩放”，不是三张投票。
- GPR/CFTC/SPDR 是慢变量/滞后变量；不能每日更新故事。
- 任何特征在 `MISSING/DEGRADED/PROXY/REVISED_ONLY` 时，只能展示，不能作为加仓依据。

### 4.4 PIT、质量与能力门

P2 生成事实包前必须：

1. 读 `_remediation.json`；`global_block=true`、`overall=ERROR`、`config_hash_match=false` 时不得生成事实包。
2. 数据集 `score_eligible=false` 时，不进入任何加权；`feature_eligible=false` 时不生成特征。
3. `available_at <= cutoff` 且 `fetched_at >= available_at`；`PROVISIONAL` 行剔除。
4. 数据 RED/STALE/DEGRADED 时，卫星不得增加；只允许风险减仓。
5. 缺失不填 0；不用前值/均值/LLM 猜。

## 5. 组合与风控

### 5.1 硬约束

| 约束 | 值 | 违规处理 |
|---|---:|---|
| 只做多 | 是 | 禁止卖空 |
| 杠杆 | 1.0 | 禁止融资/期货 |
| 核心 | 60–80%，默认 70% | 越界季度再平衡 |
| 卫星 | 0–20%，硬上限 30% | 超出即停止 |
| 现金 | ≥0 | 不得为负 |
| 总敞口 | ≤100% | 不得超配 |
| 单笔订单 | ≤20 日 ADV 5% | 拆分/延后 |
| 数据 RED | 不加仓 | 只减/空仓 |
| 账本断链 | 停止新决策 | 人工修复 |
| 配置哈希不符 | 停止 | 回滚配置 |

### 5.2 回撤阶梯

| 回撤 | 动作 |
|---|---|
| <10% | 正常 |
| 10%–15% | 卫星上限减半；禁止加仓；加强披露 |
| 15%–20% | 卫星降到 0；核心降到 60%；现金 40% |
| ≥20% | 熔断；停止新增风险；人工签字 + 书面重启清单 |

回撤阈值要在 P3 用历史样本校准；如果用户的风险承受力更低，可以整体下调，但不能放宽到“没有硬闸”。

### 5.3 风险度量

- 1 日 VaR 95/99、CVaR 95/99（至少 500 日历史模拟）。
- 年化波动、最大回撤、Calmar、Sortino、换手、跟踪误差。
- 压力测试：黄金 −10%、美元 +5%、实际利率 +100bp、人民币 ±5%、ETF 流动性 −50%、隔夜跳空 3%。
- 集中度：单 ETF、单日成交量、单一信号。
- 数据风险：GPR 修订、COMEX/WTI 零成交、US10Y 缺失、SPDR 低覆盖；对应能力门。

### 5.4 流动性与执行风险

- 518880 流动性通常好于 159934；默认 518880。
- 订单不超过 20 日 ADV 5%；大单拆分为多日/多笔。
- 溢价/折价过滤；没有 NAV/iNAV 时，只交易主 ETF，并提高滑点假设。
- 开盘/尾盘 15 分钟不交易；避开公告/停牌/涨跌停。
- 人工执行可能延迟；决策卡给价格带和有效期，过期不追。

### 5.5 模型、数据与操作风险

- 模型风险：参数不确定性、regime 变化、样本外失效；P3 必须做 walk-forward、PBO、DSR、参数敏感性。
- 数据风险：源站改版/限流/修订；原始快照、质量闸、doctor 能力门。
- 操作风险：人工漏单、错单、晚单；纸面账本、对账、`UNFILLED`。
- 合规风险：不接券商、不保存凭证、不对外分发数据。
- 停止条件：数据 RED、账本断链、配置不符、回撤 ≥20%、LLM/系统异常；任何停止都要人工签字才恢复。

## 6. 回测与验证

### 6.1 回测口径

- 事件驱动、日频；不使用未来数据；T 日收盘信号，T+1 开盘/09:45–10:30 成交。
- 标的：518880 为主；159934 用于流动性对照；SGE/GC 只做信号/基差。
- 时间：518880 从 2013-07-29；SGE 从 2016-12-19；GC 从 2016-10-19；AU0 原始接口最早 2008-01-09，但按 `settlement>0` 剔除后规范化数据从 2010-06-08 起；USDCNY 两条序列按可用期。
- 成本：佣金 2.5bps（最低 5 元）、滑点 5bps（压力 15bps）、整手 100 份、ETF 免印花税、跟踪误差/基金费用。
- 分红/拆分：用总收益；没有复权因子就用“价格 + 现金分红”手工表，标 `PRICE_ONLY`。
- 停牌/涨跌停：无法成交记 `UNFILLED`，不得假设成交。
- 现金：0 或保守利率；不得把现金收益算成黄金收益。
- PIT：所有信号按 `available_at` 对齐；GPR `REVISED_ONLY` 不进入晋升统计；`PROVISIONAL` 剔除。
- 样本外：至少 5 年；训练 3 年/测试 1 年/步进 1 年；purge/embargo 5 个交易日；测试段不调参。

### 6.2 基准

| 基准 | 定义 | 用途 |
|---|---|---|
| B0 | 100% 现金 | 机会成本 |
| B1 | 100% 518880 | 黄金 beta |
| B2 | 70% 518880 + 30% 现金，季度再平衡 | 简单配置对照 |
| B3 | 确定性规则（本设计） | 与 B1/B2 对照 |
| B4 | LLM shadow（可选） | 只做前瞻评估，不做历史回测 |

### 6.3 预注册假设

在跑数前冻结以下假设，写入 `report/research/preregistration.md` 并记录哈希：

- **H1**：200 日趋势 + 波动缩放 + 回撤闸，在 2014–2026 样本外相对 B1 改善 MaxDD/Calmar，且 Sharpe 不下降超过 0.10。
- **H2**：每周再平衡相对每日再平衡降低换手 ≥50%，风险调整收益不劣化。
- **H3**：宏观/CFTC/SPDR/GPR overlay 在成本后是否增加价值；若不显著，删除，不保留“装饰性因子”。
- **H4**：ETF 溢价/折价过滤改善执行价格，不改变信号本身。
- **H5**：卫星上限 20% 与 30% 的对比；若 30% 没有更好的风险调整收益，保留 20%。

每个假设都要写：指标、窗口、样本切分、成本、失败条件、`n_trials`。跑完后改任何一项，必须重开实验并保留旧结果。

### 6.4 统计与过拟合

- 报告 CAGR、年化波动、Sharpe、Sortino、MaxDD、Calmar、换手、跟踪误差、VaR/CVaR。
- PBO < 0.5；Deflated Sharpe 带 `n_trials`；参数 ±20% 敏感性；成本加倍；不同 regime 子样本。
- 多重检验：FDR/Bonferroni；报告所有尝试过的指标组合、窗口、阈值，不只报最优。
- 重叠样本：分块 bootstrap 或间隔采样；不能把连续多日当独立样本。
- 结果必须能回到逐日持仓、交易、成本、数据快照与配置哈希。

### 6.5 通过/不通过

**通过条件（建议）**：

1. 样本外 ≥5 年，训练/测试按 walk-forward，purge/embargo 生效。
2. 成本后 Sharpe 不低于 B1 超过 0.10；MaxDD 至少改善 3pp；或 Calmar 改善可解释。
3. PBO < 0.5；DSR 在 `n_trials` 校正后显著；参数 ±20% 不翻转；成本加倍不反转。
4. 回撤/换手/流动性约束全部满足。
5. 纸面 20 日无断链、无越界、无人工不可执行订单。

**不通过**：退回 B2，不强行上线；把失败结果写入报告，不删。

### 6.6 纸面与 shadow

- P4：确定性引擎 + 纸面账本 20 个交易日；记录决策、意图、成交、未成交、估值、对账。
- P5：LLM shadow 8–12 周（可选）；不进入人工清单；评估引用审计、失败率、时延、内存、与 B3 的差异。
- P8：用户签字后才决定是否进入 `LLM_IN_BAND`；本设计建议**不进入**，除非有明确增量证据。

## 7. LLM 与多智能体

### 7.1 结论

**v1 不使用 LLM 决定仓位。** 理由：

- 16GB/2GB 硬件上，8B/9B CPU 推理慢，9 角色两轮 12min 预算过紧；
- LLM 输出非确定，不能逐位复现；
- 多角色长文容易产生叙事偏差和“看起来合理”的伪证据；
- 没有证据表明 9 角色辩论能稳定提高风险调整收益；
- 交易决策需要可审计的确定性公式，而不是自然语言投票。

### 7.2 如果保留 LLM：3 角色 shadow

| 角色 | 输入 | 输出 | 权限 |
|---|---|---|---|
| 宏观/实际利率评论 | 事实包中的宏观/汇率/波动 | 风险提示、反方 | 无目标仓位 |
| 风险批评者 | 事实包、当前组合、回撤 | 触发项、失效条件 | 可否决到“只减”建议 |
| 魔鬼代言人 | 事实包、主策略结论 | 最强反方、证伪条件 | 无目标仓位 |

- 单轮，不搞两轮辩论；每角色 ≤60s；总预算 ≤5min。
- 只读事实包；不读新闻原文、不联网、不调用工具。
- 输出 JSON；必须引用 `fact_id`；数字不符/编造即 invalid。
- LLM 不能输出 `target_satellite_pct`；只能输出风险标记与文字解释。
- 失败/超时/解析失败 → 确定性引擎继续，LLM 结果丢弃。
- 模型优先 4B/7B 做快速检查；8B 只做每周深度复盘；单实例。
- 内存门槛用实测值，不用占位 9.5GB；起模型前测 `MemAvailable`，不达标直接 off。

### 7.3 如果用户坚持 9 角色

- 只允许每周一次 shadow，不做每日；
- 不进入人工清单、不影响目标仓位；
- 先做 5 个真实交易日试跑，记录时延、内存、JSON 合法率、引用审计失败率；
- 8–12 周评估无增量证据就关闭；
- 任何情况下不得让 LLM 直接决定真实仓位。

## 8. 系统架构与阶段计划

## 10. 参考项目取舍

> 以下基于 2026-10-29 对项目 README 的核对；均为研究/教学型项目，不能把它们的演示结果当成 alpha 证据。只借工程形状，不复制其投资逻辑或重型依赖。

| 项目 | 可借鉴 | 不照搬 | 在本设计中的位置 |
|---|---|---|---|
| [AI Hedge Fund](https://github.com/virattt/ai-hedge-fund/tree/main) | 多角色分层、模拟账本、参数化组合、哈希留痕 | 不接真实交易所也要防止误接；LLM 股票人格、重框架 | 研究/解释层；不决定仓位 |
| [AI 多 Agent 量化投资系统](https://github.com/2464404039/a-share-agents) | 多源数据降级、A 股规则、中文报告 | 19 个 Agent、FastAPI/React、重型服务 | 数据降级/中文可读性 |
| [AI Hedge Fund API v2](https://github.com/tbdavid2019/ai-hedge-fund-API) | 健康探针、检查点、PIT、可观测性 | FastAPI 常驻服务、云模型、账号体系 | CLI/日志/链路状态 |
| [Alpha Desk](https://github.com/JingHao-Leon/dsh-alpha-desk) | 合规门禁、预测台账、配置化策略 | 完整 Web 前后端、复杂权限 | 纸面账本/预测校准 |
| [TradingAgents](https://github.com/TauricResearch/TradingAgents) | 多空/风控/组合经理的辩论形状、结构化输出 | LangGraph、并发多模型、自动执行 | 可选 3 角色 shadow |
| [TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN/tree/v3.0) | 中文化、A 股制度、国产模型 | MongoDB/Redis/Vue、19 人格、向量库 | 中文术语/本地化 |
| [TradingAgents-Astock](https://github.com/simonlin1212/TradingAgents-astock) | T+1、涨跌停、整手、交易时段 | 自动下单、券商接口 | ETF 执行规则 |
| [aiagents-stock](https://github.com/oficcejo/aiagents-stock) | Streamlit、Docker、数据降级、可读性 | 股票财报/龙虎榜因子、复杂前端 | P6 UI/P7 部署 |

**共同结论**：

- 这些项目的强项是工程演示、可读性和多源数据；弱项是**没有可复现的样本外 alpha 证据**。
- 多智能体辩论适合研究/解释，不适合作为每日真实仓位的唯一依据。
- 国内黄金的约束是 ETF 交易规则、人民币汇率、数据质量、人工执行和成本；不是“Agent 数量不够多”。
