### B1. 两份「事实源」并存且冲突，无用户裁决记录

- 证据：`国内黄金量化投资设计.md:5` 自称「两者冲突时，以本文件§9 的修改清单为准」；`:606` 称「未回写前……投资决策按本文件执行」。而 `AGENTS.md` §0.4 第 15 条规定「本文件是行为单一事实源……不得复制出第二套互相矛盾的规则」。
- 现状：该文档（v1.0，2026-10-29）在 AGENTS.md、看板、CHANGELOG 中**零引用**（现跑 grep 全仓 *.md 仅命中其自身标题）；无看板任务、无 CHANGELOG 条目、无用户裁决。AGENTS.md 仍 v1.1（9 角色、每日决策、七组权重），`strategy.yaml:9-16` 仍是七组权重，`llm.yaml:27` 仍 `mode: shadow`（新设计要求 v1 `off`）。
- 违反标准：私募的研究/生产规范必须有唯一、版本化、经审批的策略规格书；两份规格并存等于没有规格。
- 建议：P2 开工前由用户裁决——采纳新设计（按 §9 清单回写 AGENTS.md 并递增版本）、部分采纳、或否决；裁决结果进看板与 CHANGELOG。**这是 P2 的前置闸。**

### B2. 版本控制失效：gitignore 把数据层源码整包排除；「P1 init」提交不完整，新鲜克隆跑不起来

- **评审期间外部状态变化（现读）**：2026-11-09 21:07:52 +0800 出现提交 `ca3fbfe "P1 init"`（36 文件，+8903/-73），工作区随之只剩 `?? report/`。本报告 §1 的 git 读数已按提交后重读。
- **但该提交不含数据层**：`git ls-files | grep -c 'gold/data/'` = **0**（现跑）。机制是 `.gitignore:232` 的裸 `data/` 规则匹配任意层级目录，把源码包 `src/main/.../gold/data/` 整体忽略（`git check-ignore -v` 现跑命中 normalize.py、adapters/base.py）；同文件 :236-240 还逐行忽略了 3 个 `__init__.py`。
- **后果（现读推证）**：`cli.py:43-57` 导入 10 个 `gold.data.*` 模块，全部不在 HEAD——**克隆 ca3fbfe 后任何数据命令都 ImportError**。测试同样缺：HEAD 只有 12/22 个测试文件、11/32 个 main 源文件。磁盘上 pytest 仍 `215 passed`（现跑 EXIT=0），因为被忽略的文件还在本机——「测试全绿」掩盖了「仓库不完整」。
- **llm.yaml 的 10-26 改动已随提交固化**，仍无 CHANGELOG 条目；Q3 判红不受提交影响（数据与配置哈希仍不一致）。
- 违反标准：版本控制必须完整可重放；「提交了但核心包缺失」比「没提交」更危险——它制造已归档的假象。
- 建议：①`.gitignore` 的 `data/` 改 `/data/` 锚定根目录，删掉对 `__init__.py` 的逐行忽略；②补交 `gold/data/` 源码包与缺失测试文件（显式路径，不 push）；③用 `git archive HEAD` 解到临时目录跑 pytest 证明克隆可跑（这是「提交完整性」的验收闸）；④llm.yaml 改动补 CHANGELOG。
