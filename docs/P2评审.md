## 0. 一页结论

1. **P1 的数据面已经足够支撑 P2 的「算得出」，但不足以支撑 P2 的「按字面判得出」。** 阻断的根源不是缺代码，而是 `AGENTS.md` 里三处规则互相顶牛、且有三件 P2 必须用的东西在时间线上还没被造出来（当前仓位、`T_det` 定义、P2 验收闸）。
2. 最硬的一条：按 §6.9 硬约束 2 的字面读法（一个数据集 `score_eligible=false` 就剔除它所在的**整组**权重），再叠 §8.2「缺失超过 2 组 → `DEGRADED`」，**P2 上线第一天就会把 cross_market / macro / flows / geopolitics 四组同时剔掉，判成 `DEGRADED`——只减不加**。而按另一读法（组内特征级重归一）则四组都还有可用特征、可正常出分。两种读法给出相反的当日模式，必须先定口径。
3. 建议裁决顺序：先定 B1/B2/B3（口径与输入契约），再动 M1–M6（注册表、标准化公式、单位、PIT 对齐、开关拆分、验收闸），L1–L5 与首批实现同批带走。

## 2. 阻断项（B1–B3）：不裁决则 P2 交付即失真

### B1 「被 doctor 封锁的组」算不算 §8.2 的「缺失组」

- 现象：§6.9 硬约束 2 写「任一数据集 `score_eligible=false` 时，**其组权重**按 §8.2 的缺失规则剔除并重新归一」；§8.2 写「缺失组按剩余权重重新归一；**缺失超过 2 组 → `DEGRADED`**」。现读有 6 个数据集 `score_eligible=false`，它们分属 cross_market（`comex_gc`/`wti_cl`）、macro（`us10y`）、flows（`spdr_gold`）、geopolitics（`gpr`/`geo_events`）。
- 两种读法的后果完全相反：
  - **读法一（数据集→整组剔除）**：四组被剔 > 2 → 每天 `DEGRADED` → 卫星仓永远只减不加，P2 的仓位带与 `T_det` 失去意义，§18.3 P2 表「RED 只减不加」一格恒真。
  - **读法二（组内特征级剔除）**：cross_market 仍有 `XMK_AU_SGE_BASIS`/`XMK_INNER_OUTER_PREMIUM`/`XMK_USDCNY`；macro 仍有 `MAC_USDCNY`；flows 仍有 `FLOW_CFTC_NET_PCT`/`FLOW_ETF_VOL_Z`；geopolitics 仍有 `GEO_MARKET_STRESS`/`GEO_NEWS_COUNT`（`wti_cl price_only` 允许收盘价类 5 日变化）→ 0 组缺失，正常出分，可加仓。
- 附带同名冲突：`DEGRADED` 在 §4.3 是**运行模式**（核心数据缺失/过期/单位异常），在 §8.2 是**特征缺失计数**后果，在 §7.4 是**行级/字段级标记**。三处共用一个词，判据与 UI 会分叉。
- 待裁决（推荐甲）：
  - **甲**：按读法二（组内特征级重归一）为 P2 口径，并在 §8.2/§6.9 各补一句「组是否缺失由该组**可用特征数**判定：0 个可用才算缺失组」；同时把 §8.2 的后果改名 `FEATURES_INSUFFICIENT`，与模式 `DEGRADED` 分开。
  - **乙**：按读法一（数据集→整组剔除），接受 P2 期间常态 `DEGRADED`，并把「解封」写成显式前置任务（补 TIPS/DXY 官方源、GPR vintage、SPDR 历史、事件复核）。
  - **丙**：先只落地 trend/momentum/volatility 三组（价格类，全绿），其余四组标 `PLAN_ONLY` 不进分数——等于缩小 P2 范围。

### B2 仓位带与风控要用的「当前卫星仓 / 高水位 / core」在 P4 才存在

- 现象：§8.3 风险调整三条都要 `min(H, 当前卫星仓)`；§9.3 `satellite_cap = min(30%, 100% - core - cash_floor)`；§9.5 回撤分级以「gold sleeve 历史高水位」为基准；§9.6 换手要 `sum(|Δsatellite|)/avg_satellite`。而纸面账本 `data/paper/ledger.jsonl`、NAV、对账是 **P4** 交付（§18 路线图、§13）。
- 后果：P2 若按字面实现，这几条闸要么静默跳过（等于没有风控），要么被迫读一个不存在的账本（等于编数）。
- 待裁决（推荐甲）：
  - **甲**：P2 新增人工输入契约 `data/manual/portfolio_state.csv`（字段 `as_of/core_pct/satellite_pct/cash_pct/high_water_nav/source/available_at`，§6.3 手工层五要素齐全），并把「无该文件时相关闸一律 `MISSING` 且**只减不加**」写进 §8.3/§9.5 与 P2 验收判据。代价：用户每天手填一行（或按周填）。
  - **乙**：P2 只交付 `[L,H]` 与分数、regime、trace，**不做**「与当前仓位取 min」「回撤分级」「换手」三条，把它们推到 P4 与账本同时落地。代价：§18.3 P2 表「RED 只减不加 / veto→0」两格要改成 P4 判据，需同批作废旧句。
  - **丙**：用固定夹具仓位（`core=70/satellite=0/high_water=1.0`）跑 P2 全部测试，生产入口显式拒绝（`MODE=FROZEN_NO_PORTFOLIO`）。代价：P2 输出不得进决策卡，只能算「研究产物」。

### B3 `T_det` 全文没有定义

- 现象：§2.2 决定 1、§4.3 `DETERMINISTIC`、§11.7 聚合与回退都把 `T_det` 当最终交付物，但 §8 只算到 `[L,H]`（区间），没有任何一句写「`T_det` 取区间内哪一点」。§18.3 P2 表与 §17.6 风控不变量都只约束边界。
- 后果：LLM 缺位时的兜底目标无法复现，P4 决策卡与 P5「≥2 角色失败→`T_det`」全部悬空。
- 待裁决（推荐甲）：
  - **甲**：分数在区间内线性插值取点 + 滞回带（`|新−旧| < risk.turnover.noise_band_pp` 时保持旧值）。可复现、换手可控、与 §9.6 噪声带天然一致。
  - **乙**：带内离散格点（每 5pp 一档），取「不超过基础分数对应档」的最高档。更钝、更可解释，但边界抖动要另配滞回。
  - **丙**：`T_det = (L+H)/2`（区间中点）。最简，但每天跟着分数跳、与「高波动压缩上限」叠加时容易制造无意义换手。
  - 无论选哪档，都必须在 `strategy.yaml` 新增 `t_det.*` 段（方法、格点步长、滞回引用键），代码不写魔法数（§15.5）。

## 3. 重要项（M1–M6）：P2 开工前要有可验收答案

### M1 特征注册表不存在，且首批 fact_id 里有三个先天无源

§7.1 要求每个特征在 `features/registry.yaml` 注册 12 个字段；§18.3 P2 验收第一格就是「每个特征 12 个字段齐全、`fact_id` 唯一」。现读：文件全盘不存在。同时 §7.2/§7.3 点名的 fact_id 里：`MAC_TIPS10Y`（§6.1 明写无源，需手工 CSV 或代理）、`MAC_DXY_PROXY`（需按 ICE 公式用 BOC 六币种构造，P1 未实现）、`GEO_EVENT_SEVERITY`（现读被 `blocked_features` 封锁）。
建议：P2 首批 registry 只登记「有源且 `score_eligible` 允许」的特征，其余三条带 `missing_policy` 显式登记为 `MISSING/PROXY/`封锁，并在架构测试里断言「registry 里每个 fact_id 的 `source` 都能在 `data_sources.yaml` 或手工层找到落盘文件」。

### M2 「每组先标准化到 [-100,+100]」没有公式、没有配置键

§8.2 只写了目标区间。z 分？分位差？截面 rank？样本不足怎么办？`strategy.yaml` 里没有任何 `feature_std`/`score` 段。这条不定义，P2 的「确定性/可复现」闸（§18.3 P2 表「同输入同 `fact_pack_hash`」）测不到分数层。
建议：新增 `strategy.yaml` 的 `score.standardization: {method, window, clip, min_samples, on_insufficient}`，并把「同输入两次分数逐位相同」做成 P2 判据。

### M3 单位口径冲突与缺键

- `regime.hysteresis.band: 0.05` 注释「单位：比例（5 个百分点）」，而同段 `low_pct/high_pct/crisis_pct: 30/70/90` 注释「单位：%」——两个数放在同一处判断里必然写错一侧（`0.05` vs `5`）。
- `VOL_PCT_1Y` 的「1 年」分位窗口在 §7.2/§7.3 被引用，但 `strategy.yaml` 只有 `geo.gpr_z_window: 252`，**没有波动分位窗口键**；`risk.target_vol_annual: 0.12` 也没有年化系数（√252 还是 √250）。这两处不写死口径，回放哈希对不上。
- 建议：分位/年化系数/窗口全部进 `strategy.yaml`，并在 `config/loader.py` 加载期校验单位（同批见 L1）。

### M4 跨市场价差的 PIT 对齐规则缺失

现读：`comex_gc`/`wti_cl` 各有 1 行 `2026-11-11` 的 `PROVISIONAL`（`available_at=2026-11-12T06:00+08:00`），07:00 冻结事实包时境外只能用 `2026-11-10`，而 `sge_au9999`/`etf_518880`/`shfe_au0` 能用 `2026-11-11`。`XMK_GC_SGE_SPREAD`、`XMK_INNER_OUTER_PREMIUM` 若按「各自最新可得」取值，就是**境内 T / 境外 T-1 的错日价差**（既不是未来函数也不是可比价）。
建议：P2 明确「跨市场特征只允许同 `as_of` 对齐，缺日则该特征 `MISSING`」（可复现、可判定），并在 §7.2 补一句；或声明允许滞后并用 `lag_days` 显式命名（`XMK_GC_SGE_SPREAD_LAG1`）。

### M5 `contrarian.enabled` 一枚开关管格言两半句

§8.4.1 明确前半句（贪婪→恐惧）的**降险**在 v1 允许、后半句（恐惧→贪婪）的**加仓**须先过 §12.7；现读 `strategy.yaml:82` 只有一个 `contrarian.enabled: false`。按字面：`false` 时前半句的降险动作也无处触发；若为了放前半句改成 `true`，就把未过门槛的加仓方向一起打开了——**方向相反的两种风险共用一个布尔**。
建议：拆 `contrarian.reduce.enabled`（默认 true）与 `contrarian.add.enabled`（默认 false，且 `add.enabled=true` 需 §12.7 七条 + 用户签字的加载期校验），加载期拒绝「add 开而未预注册」。

### M6 P2 没有验收闸

现读 `accept --stage P2` → EXIT=2 `verdict=ERROR`。§18.3 P2 表有 8 行验收项（注册表完整、事实包 PIT、确定性、仓位不变量、regime 滞回、缺失策略、逆向原型只读、无 LLM 参与），全部无程序判据；§18.1 纪律 2 还要求 P2 至少一条负对照。
建议：P2 落 `acceptance/p2.py` + `cli.py accept --stage P2`，判据建议编号 P2-C1…（事实包 PIT 双条件 `available_at<=cutoff` 且 `fetched_at>=available_at`、`PROVISIONAL` 剔除、截断未来数据后历史 `fact_pack_hash` 不变、`0≤L≤H≤30%`、`core+satellite+cash=100%`、`cash≥0`、能力清单必读、逆向原型零动作），阈值进 `application.yaml` 的 `acceptance` 段并扩 `Q3` 同版本闸到 P2。负对照至少两枚：注入 `available_at>cutoff` 行、绕过 `_remediation.json` 重算「能不能用」。
